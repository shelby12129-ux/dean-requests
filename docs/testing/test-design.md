## Что такое тест-дизайн

Тест-дизайн — проектирование тестов ДО написания кода.
Сначала таблица классов эквивалентности и граничных значений,
потом — автотесты.

---

## 1. Авторизация

### Поле «Логин»

| Вход | Ожидание |
|------|----------|
| `student1` | Успешный вход |
| `employee1` | Успешный вход |
| `unknown` | None |
| `""` (пусто) | None |
| `None` | None |

### Поле «Пароль»

| Вход | Ожидание |
|------|----------|
| `pass123` | Успешный вход |
| `wrong` | None |
| `""` (пусто) | None |
| `None` | None |

---

## 2. Регистрация заявки

| Вход | Ожидание |
|------|----------|
| Имя + описание | Заявка создана |
| `""` + описание | ValueError |
| Имя + `""` | ValueError |
| `""` + `""` | ValueError |
| 100 символов | Принимается |
| 500 символов | Принимается |

---

## 3. Назначение исполнителя

| Условие | Ожидание |
|---------|----------|
| Заявка NEW | Статус → IN_PROGRESS |
| Заявка IN_PROGRESS | ValueError |
| Заявка CLOSED | ValueError |
| ID не существует | ValueError |

---

## 4. Закрытие заявки

| Условие | Ожидание |
|---------|----------|
| Заявка DONE | Статус → CLOSED |
| Заявка NEW | ValueError |
| Заявка IN_PROGRESS | ValueError |
| ID не существует | ValueError |

---

## 5. Стратегия «Наименьшая загрузка»

| Условие | Ожидание |
|---------|----------|
| 3 разных загрузки | Наименее загруженный |
| 2 доступных, 1 off_duty | Из доступных |
| Все off_duty | None |
| Пустой список | None |
