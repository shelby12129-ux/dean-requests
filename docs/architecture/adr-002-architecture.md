# ADR-002: Монолитная архитектура

## Статус

Принято. 12.10.2026.

## Контекст

Нужно выбрать архитектурный стиль: монолит или микросервисы.

**Факторы:**
- Команда из 2 человек.
- Учебный проект, срок — семестр.
- Нагрузка: до 2000 студентов, ~50 сотрудников деканата.
- Требуется быстрый старт и простое развёртывание.

## Рассмотренные варианты

### Вариант 1. Микросервисы

Каждая функция — отдельный сервис (авторизация, заявки, уведомления).

**Плюсы:**
- Независимое развёртывание.
- Масштабирование по частям.

**Минусы:**
- 2 человека не потянут поддержку 4 сервисов.
- Сложное межсервисное взаимодействие.
- Избыточно для учебного проекта.

### Вариант 2. Монолит

Одно приложение со всеми модулями.

**Плюсы:**
- Быстрый старт разработки.
- Простое развёртывание.
- Не требует инфраструктуры для нескольких сервисов.
- Команда из 2 человек справится.

**Минусы:**
- При росте нагрузки нужно распиливать.
- Один процесс — единая точка отказа.

## Решение

**Выбран монолит.**

Обоснование: для команды из 2 человек и учебного срока
монолит — единственный реалистичный вариант. Микросервисы
требуют инфраструктуры и опыта, которых нет.

## Последствия

**Что проще:**
- Разработка и отладка в одном процессе.
- Развёртывание: один Docker-контейнер.
- Тестирование: один набор тестов.

**Что дороже:**
- При росте команды — сложность координации.
- Один процесс на всё.

**Принятые риски:**
- Если проект вырастет — потребуется рефакторинг.
- Единая точка отказа — приемлемо для учебного проекта.
