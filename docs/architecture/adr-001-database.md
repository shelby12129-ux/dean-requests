# ADR-001: Выбор СУБД SQLite

## Статус

Принято. 12.10.2026.

## Контекст

Нужно выбрать систему управления базами данных для хранения
заявок, справочников и пользователей.

**Требования, влияющие на решение:**
- НФТ-1: время формирования отчёта — не более 5 секунд при 10 000 записей.
- НФТ-8: резервное копирование раз в сутки.
- Один сервер, команда из 2 человек.
- Развёртывание в учебной среде.

## Рассмотренные варианты

### Вариант 1. SQLite

**Плюсы:**
- Один файл — простое резервное копирование.
- Не требует установки сервера.
- Достаточна для нагрузки 1000–2000 студентов.
- Простой старт разработки.

**Минусы:**
- Плохо масштабируется на многопользовательский режим.
- Ограничение одновременных записей.

### Вариант 2. PostgreSQL

**Плюсы:**
- Промышленный стандарт.
- Многопользовательский режим.
- Богатая функциональность.

**Минусы:**
- Требует установки и настройки сервера.
- Избыточен для учебного проекта.
- Сложнее резервное копирование.

## Решение

**Выбран SQLite.**

Обоснование: для учебного проекта с нагрузкой до 2000 студентов
SQLite достаточна. Простота развёртывания и резервного копирования
важнее масштабируемости, которая в учебном проекте не востребована.

## Последствия

**Что проще:**
- Развёртывание: копирование файла.
- Резервное копирование: `cp db.sqlite backup/`.
- Локальная разработка: без сервера.

**Что дороже:**
- Миграция на PostgreSQL при росте нагрузки.
- Многопользовательский режим — только на чтение.

**Принятые риски:**
- При росте нагрузки потребуется миграция на PostgreSQL.
- Ограничение одновременных записей — не критично для деканата.
