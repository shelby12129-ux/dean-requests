# Спецификация требований (SRS)

Проект: «Система учёта заявок студентов в деканате»
Версия: 1.0
Дата: 12.10.2026
Автор: Ишанов Афроз (аналитик), Рахматуллозода Чехрон (тестировщик)

## 1. Назначение

Документ описывает функциональные и нефункциональные требования
к системе учёта заявок студентов в деканате. Спецификация —
источник для разработки, тестирования и приёмки.

## 2. Область применения

Система автоматизирует:
- подачу заявок студентами;
- обработку заявок сотрудниками деканата;
- отслеживание статуса заявки;
- формирование отчётов.

## 3. Функциональные требования (ФТ)

### ФТ-1. Регистрация заявки

Система должна регистрировать заявку студента с присвоением уникального номера.

### ФТ-2. Автоматическое назначение исполнителя

Система должна назначать исполнителя автоматически по критерию наименьшей загрузки.

### ФТ-3. Просмотр статуса заявки

Система должна показывать студенту статус его заявки в личном кабинете.

### ФТ-4. Уведомление при смене статуса

Система должна отправлять e-mail-уведомление студенту при изменении статуса заявки.

### ФТ-5. Формирование отчёта по заявкам

Система должна формировать отчёт по заявкам за выбранный период.

### ФТ-6. Ведение справочника студентов

Система должна вести справочник студентов: добавление, редактирование, удаление.

### ФТ-7. Поиск заявок

Система должна искать заявки по номеру и ФИО студента.

### ФТ-8. Фильтрация заявок

Система должна фильтровать заявки по статусу, типу и исполнителю.

### ФТ-9. Закрытие заявки

Система должна закрывать заявку с фиксацией даты и результата.

### ФТ-10. Отмена заявки студентом

Система должна позволять студенту отменить заявку в статусе «Новая».

### ФТ-11. Управление типами заявок

Система должна вести справочник типов заявок: справка, пересдача, академический отпуск.

### ФТ-12. Управление пользователями

Система должна управлять пользователями и назначать им роли.

### ФТ-13. Прикрепление файлов

Система должна позволять прикреплять файлы к заявке (PDF, до 5 МБ).

### ФТ-14. Авторизация

Система должна авторизовывать пользователей по логину и паролю.

### ФТ-15. Журнал изменений

Система должна фиксировать все изменения статуса заявки с датой и автором.

## 4. Нефункциональные требования (НФТ)

### НФТ-1. Производительность отчёта

Время формирования отчёта — не более 5 секунд при 10 000 записей.

### НФТ-2. Производительность списка

Список заявок загружается не дольше 2 секунд при 1000 записей.

### НФТ-3. Безопасность доступа

Доступ к данным студентов — только у роли «Сотрудник деканата» и «Администратор».

### НФТ-4. Хранение паролей

Пароли хранятся в хешированном виде (bcrypt, cost ≥ 12).

### НФТ-5. Кроссбраузерность

Система работает в браузерах Chrome и Firefox последних версий.

### НФТ-6. Доступность

Система доступна не менее 99% времени в месяц.

### НФТ-7. Удобство интерфейса

Новый пользователь находит нужную функцию не более чем за 3 клика.

### НФТ-8. Резервное копирование

Резервное копирование данных выполняется раз в сутки.

## 5. Ограничения

- Стек: Python + SQLite.
- Сервер: 4 ГБ ОЗУ, 50 ГБ диска.
- Приёмка проекта — до конца семестра (неделя 15).

## 6. Допущения

- Все пользователи имеют доступ к интернету и браузеру.
- SMTP-сервер университета доступен и настроен.
- Деканат выделит сотрудника для обучения.
